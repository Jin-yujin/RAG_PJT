## 자동 테스트 범위

- 메타데이터 수/ID/URL 유일성과 수집 허용 범위.
- 고정 ID 메타데이터 재색인 시 중복 방지.
- 외부 문서 재색인 중복 방지와 청킹 설정 변경 시 오래된 청크 정리.
- 동일 원문을 여러 항목에 연결할 때 덮어쓰기 방지.
- 검색의 항목 필터 적용.
- 답변에 실제 인용한 근거만 남기는 후처리.
- 존재하지 않는 근거 번호의 답변 차단.
- 공식 문서 근거가 없을 때 생성 호출 생략.
- JSON/설정값 검증, 설명문 추출 시 코드 제외와 저작권 문구 보존.
- 허용하지 않는 URL과 별도 라이선스 검토 대상 경로 거부.

자동 테스트의 DB 검사는 테스트용 벡터를 사용합니다. 실제 의미 검색 확인은 위 별도 행의 로컬 모델 실행 결과입니다.
인용 번호 검사와 의미 검색 성공은 답변 내용의 정확성이나 인용의 사실적 타당성을 보장하지 않습니다.

## 사용자 PC에서 확인할 체크리스트

- [ ] requirements.txt 설치 및 GMS 세 설정값 입력.
- [ ] scripts/index_data.py를 두 번 실행해 메타/문서 청크 수가 늘지 않는지 확인.
- [ ] ‘앱 서명’에서 키의 차이를 질문하고 원문과 대조.
- [ ] ‘Compose 상태 관리’에서 상태 호이스팅을 질문하고 원문과 대조.
- [ ] 문서에 없는 미래 API를 질문해 확인되지 않는다고 답하는지 확인.
- [ ] 항목을 바꿔 이전 대화가 섞이지 않는지 확인.
- [ ] 조건 검색에 확인 가능한 조건/없는 조건을 각각 넣어 비교.
- [ ] 학습 가이드의 주요 주장과 근거 번호를 대조.

- [ ] 같은 질문 반복 시 원문 및 검색어 캐시 재사용 확인.
