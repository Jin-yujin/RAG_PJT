# 요구사항 정의서

문서 버전: 1.0 / 작성일: 2026-10-22 / 대상: 원본 starter 기반 제출본

## 1. 서비스 개요

Android 개발 입문자가 공식 설명 자료를 찾아 학습할 수 있도록 돕는 비공식 한국어 RAG 멘토다. 사용자는 학습 항목을 고르거나 자연어 조건으로 탐색한 뒤, 공식 문서를 근거로 질문하고 인용 원문을 확인한다. 대상 환경은 Windows, VS Code, Python 3.12, 웹 브라우저다.

## 2. 범위와 완료 기준

기본 기능 F2001~F2012를 중심으로 구현하되 F2004는 허용 목록 안의 후보 탐색으로 부분 대응한다. 심화 F2013~F2016은 제외한다. 구현 여부와 실제 모델 응답 검증 여부는 별도로 판정한다.

- 입력: 선택 항목, 질문 또는 자연어 탐색 조건.
- 출력: 한국어 답변, 사용한 근거 번호, 원문 링크와 출처, 처리 시간.
- 데이터: 직접 작성한 항목 112개와 수집한 공식 설명문 3개를 초기 제공한다.
- 저장: Chroma 벡터 저장소와 로컬 원문 JSON, 세션 내 대화.
- 완료 기준: 원문 기반 질의 및 인용 표시, 항목별 대화 분리, 중복 없는 재색인, 키 제외 업로드를 확인한다. GMS를 사용하는 완료 기준은 실제 호출과 원문 대조가 필요하다.

## 3. 기능 요구사항 및 구현 대응

첨부 명세의 기본 기능을 중심으로 구성한 초기 버전입니다. 구현된 코드와 실제 검증 완료를 구분합니다.
첨부 교육 명세 원본은 대외비 표시가 있으므로 이 프로젝트 ZIP에 재배포하지 않습니다.

| 번호 | 대응 | 현재 상태와 한계 |
|---|---|---|
| F2001 | data/items.json, scripts/build_catalog.py | 직접 작성한 학습 항목 메타데이터 112건. 공식 문서를 112건 확보했다는 뜻은 아님. 항목별 원문 URL은 있지만 전체 URL 수집 성공 여부는 별도 확인 필요 |
| F2002 | Store.index_items | 실제 임베딩으로 Chroma 메타 컬렉션에 적재. 고정 ID upsert, 재실행 중복 방지 |
| F2003 | llm.keywords | GMS 모델이 JSON 검색어 생성. 항목 이름을 프로그램에서 항상 추가. 실제 GMS 키로 검증 필요 |
| F2004 | Collector.collect_for_question | 부분 대응: 공식 문서 허용 목록에서 후보 검색 → LLM 선별 → 원문 수집. 선택 항목 원문 우선 수집, 원문·검색어 캐시. 외부 검색 API를 통한 전체 사이트 검색은 미구현 |
| F2005 | Store.index_document | 별도 문서 컬렉션. 설정 파일 청킹, 항목 ID·문서 URL·청크 버전 기반 ID, 재색인 시 오래된 청크 제거 |
| F2006 | Store.retrieve | 선택 항목 메타데이터 직접 조회 + 항목 필터 의미 검색 + 텍스트 해시 중복 제거. Top-k는 외부 문서 수이며 최종 근거에는 메타데이터 1건 추가 |
| F2007 | pipeline.build_graph | LangGraph retrieve/generate 두 노드. 공식 문서 근거가 없으면 모델 호출 생략. 프롬프트로 근거 제한. 답변의 사실 정확성 자체를 보장하는 검증기는 아님 |
| F2008 | pipeline.citations, app.show_sources | 답변에서 실제 인용한 유효 번호만 표시. 존재하지 않는 번호는 답변 표시 중단. 인용 없음 안내 |
| F2009 | app.py | 항목 선택, 항목 ID별 채팅. 대화는 Streamlit 세션 메모리이며 브라우저 세션 종료 후 영구 보존하지 않음 |
| F2010 | service.learning_question | 근거 기반 Android 학습 가이드 생성. 실제 GMS 답변 검증 필요 |
| F2011 | service.explore | 메타데이터 의미 검색 후 LLM 조건 선별. 실제 GMS로 조건 일치 평가 필요. 조건 일치가 기계적으로 보장되지는 않음 |
| F2012 | app.py | 색인 없음, GMS 설정 누락, 진행 상태, 처리 시간, 일반화한 오류 표시 |
| F2013~F2016 | - | 이번 범위에서 제외 |

## 비기능 대응

- NF2001: 전체 질의 처리 시간 화면 표시. 실제 사용자 PC 성능 측정은 별도.
- NF2002: 원문 URL 캐시와 항목+검색어 캐시. 실패한 수집은 성공으로 캐시하지 않음.
- NF2003: .env, .gitignore. 실제 키는 예제에 포함하지 않음.
- NF2004: UI에서 키·프롬프트 전문·오류 추적 비노출. 컬렉션 추적은 별도 외부 서비스로 보내지 않음.
- NF2005: config/models/collector/store/llm/pipeline/service/UI 모듈 분리.
- NF2006: robots.txt 확인, 식별 User-Agent, 요청 간격, 429/서버 오류 재시도, 타임아웃.
- NF2007: URL·제공자·라이선스·수집일·변경 사항 기록. 자동 추출은 법적 검토를 대체하지 않음.

## 도메인 선택 근거

- 항목: Android 학습 주제 12개 + Android 플랫폼 API 항목 100개 = 112개.
- 메타데이터: 이름, 카테고리, 학습 수준, 직접 작성한 소개, 키워드, 원문 URL.
- 외부 출처: developer.android.com의 허용 목록 문서. 원문 자체와 메타데이터는 별도 컬렉션.
- 위험 질문 예: ‘Play 앱 서명 키와 업로드 키가 같은가?’, ‘remember로 저장한 상태는 어떤 상황에 유지되는가?’, ‘Activity가 소멸할 때 화면 상태를 어디에 두어야 하는가?’
- 의료·금융 도메인은 아님. 공식 Google 서비스로 오인되지 않도록 비공식 표시.

## 라이브러리 버전

명세의 기술 구조는 사용하지만 모든 패키지를 첨부 문서의 정확한 버전에 고정하지는 않았습니다.
요구사항에서 버전 일치도 평가한다면 담당 강사의 허용 범위를 확인한 뒤 requirements.txt를 조정하세요.
사용하지 않는 FastAPI, 직접 작성 프런트엔드, MMR, LangSmith 추적은 추가하지 않았습니다.

## 제출 시 추가할 것

실제 GMS 설정 후 질문/근거 화면, 조건 검색, 학습 가이드, 캐시 재사용, 항목별 채팅 화면을 캡처하세요.
제공된 검증표는 초기 상태이므로 실측 결과를 반영해야 합니다. 문서는 이 제출본에 포함되어 있으며, 사용자 PC 실측 결과·화면 캡처·상호 평가는 실제 수행 후 추가해야 합니다.


## 인수 검증 기준

| 검증 ID | 요구사항 | 절차 | 합격 기준 |
|---|---|---|---|
| A01 | F2001~2002 | 초기 색인을 2회 실행 | 항목 112건 유지, 중복 증가 없음 |
| A02 | F2003~2005 | 자동 수집을 켜고 앱 서명 질문 | 검색어·선별 결과 표시, 선택 항목 원문 포함, 수집 성공 문서 색인 |
| A03 | F2006~2008 | 앱 서명에서 키 차이 질문 | 해당 항목 근거 검색, 주요 주장 인용, 사용한 원문만 표시 |
| A04 | F2007 | 외부 근거 없는 항목 질문 | 자료 부족 안내, 근거 없는 생성 생략 |
| A05 | F2009 | 두 항목을 번갈아 선택 | 항목별 이전 대화 분리 |
| A06 | F2010 | 학습 가이드 생성 | 역할·핵심 개념·확인 사항과 근거 표시 |
| A07 | F2011 | 로컬 저장 관련 조건 검색 | 후보와 추천 이유 표시, 선택 후 질문 가능 |
| A08 | F2012 | 키 누락 / 빈 색인으로 시작 | 필요한 설정·색인 안내, 질문 입력 차단 |
| A09 | NF2002 | 동일 수집 요청 반복 | 원문 및 성공 검색어 캐시 재사용 표시 |
| A10 | NF2003~2007 | Git 추적 파일과 근거 펼침 확인 | 키·가상환경 제외, 원문·라이선스 고지 유지 |

심화 기능을 구현하지 않은 것을 기본 기능 검증 성공으로 바꾸어 기록하지 않는다.
